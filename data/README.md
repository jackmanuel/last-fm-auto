# Data Directory

This directory holds the input data you provide, the output files generated by scripts, and configuration data used by the scrobbler.

## Data Provenance and Licence

The bundled `artists.json` was generated from artist names in the maintainer’s personal listening history. [Last.fm Stats](https://lastfmstats.com/) retrieved the history through the [Last.fm API](https://www.last.fm/api) and exported it as CSV. The bundled list contains artist names only. The source exports are kept out of the repository.

The repository’s [MIT licence](../LICENSE) covers original project contributions, including the code and original curation. Data supplied by Last.fm is credited to Last.fm and remains subject to the [Last.fm API Terms of Service](https://www.last.fm/api/tos).

## 1. Input: A large list of song/artist pairs (CSV Files)

**Action Required:** To build the optional local track database, you must place one or more `.csv` files containing song name and artist pairs in this directory.

These title/artist pairs should match the last.fm database, since they will be scrobbled from this file exactly. To ensure this, it is recommended to download your listening history (or another user's history) from https://lastfmstats.com in CSV format. 

### Required Format

The `scripts/build_searchable_tracks.py` script will automatically find and process all `.csv` files in this folder. For a file to be considered valid, it **must** meet the following criteria:

*   **Separator**: The file must use a **semicolon (`;`)** as the column separator.
*   **Columns**: The file must contain at least the following two columns with these exact names:
    *   `Track`
    *   `Artist`

Any file that does not meet these requirements will be skipped.

## 2. Generated Files

### `artists.json`

This file is generated from the `Artist` column in the source CSV files:

```bash
python -m scripts.build_artist_list
```

The query splitting pipeline uses this list to detect artist names in raw text queries. Because source exports can contain collaboration-style artist strings, `scripts.build_artist_list` also reads the comma-artist curation files described below and removes explicitly rejected comma-containing names.

### `known_comma_artists.json` and `rejected_comma_artists.json`

These files are created by the interactive curation script:

```bash
python -m scripts.curate_comma_artists
```

The script presents every artist name containing a comma and lets you mark it as either a real canonical artist name or collaboration-style noise. This matters because real artists such as `Tyler, The Creator` and `Black Country, New Road` contain commas, while entries such as `Tyler, The Creator, DJ Drama` are usually not useful artist candidates for query splitting.

Progress is saved after every answer, so the curation can be stopped and resumed.

### `local_tracks.json`

This file is created when you run the `scripts/build_searchable_tracks.py` script. It serves as a local cache of tracks from your CSV files that contain apostrophes at the beginning or end of words in the title, since the Last.fm search API is not capable of finding these songs. The main pipeline uses this file to find matches for problematic queries instantly, avoiding unnecessary Last.fm API calls.

### `splitting_ground_truth.json`

This file is manually curated evaluation data for `evaluation/evaluate_splitting.py`. Each entry should preserve the raw input query and the expected split:

```json
{
  "query": "sometimes mbv",
  "track": "sometimes",
  "artist": "my bloody valentine"
}
```

The `query` field should stay raw, including abbreviations or misspellings. The `artist` field should use the canonical artist name expected from `artists.json`; comparison is case-insensitive in the evaluator.

## 3. Provided Files

### `abbreviations.json`

This file contains a predefined list of text substitutions used by the query cleaning pipeline (e.g., mapping `ftp` to `Foster the People`). You can customize this file with your own rules to improve matching for your specific data.
